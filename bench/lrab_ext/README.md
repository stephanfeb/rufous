# rufous-side LRAB extension

Tasks that live in this checkout, scored by Mingbird's LRAB scorer (`score_task.py`, imported
read-only by `bench/lrab_h2h.py`). Mingbird's tree is never written to. The layout is LRAB's
(`tasks/<tier>/*.json`, `fixtures/`), so the driver takes it as a task root:

```sh
python bench/lrab_ext/gen_pressure.py                      # regenerate (deterministic; tests check for drift)
python bench/lrab_h2h.py --arms rufous --task-root bench/lrab_ext \
    --ctx 16384,32768,65536 --model qwen3.5:9b --results bench/results/lrab_ctx
python bench/lrab_h2h.py --summary --results bench/results/lrab_ctx
```

Only the rufous arm runs here: Mingbird's own runner resolves fixtures against its own LRAB
root. Task checks are limited to the scorer's root-independent kinds (`exists`, `contains_any`,
`contains_groups`, `script_pass`); collateral damage is caught by a `check_collateral.py`
shipped with the fixture (prints `COLLATERAL OK` when every untouched definition is intact; in
the surface tiers only once the task's own edit has happened, else `COLLATERAL PENDING`).

## Ablation: the kernel off

`AGENT_ABLATION` names the compensations to switch off for a run; the list, with what each
switch turns off, is `crates/rufous-kernel/src/agent/ablation.rs`, and `kernel` is every
switch at once. The driver passes the environment through, so one arm is one `--results`
dir and the comparison is cell by cell against the same axes with the kernel on:

```sh
AGENT_ABLATION=kernel python3 bench/lrab_h2h.py --arms rufous --task-root bench/lrab_ext \
    --tiers tier6_editor --policy coding,unattended --model gemma4:e2b \
    --results bench/results/surface_editor/gemma_e2b_kernel_off
```

The transcript's `[ablation] off: …` line says what was off; a misspelt switch is named
there and turns nothing off. Rebuild `target/release/rufous` first. `reattribute` (2026-11-01, bead boubou-alj) is in the
list: off, an earlier turn's own refusal reply is sent to the model as it was said instead of
as a `[ledger]` line. `scope_gate` (2026-10-31)
is in the list: on, an unattended cell whose prompt reads as tracker or docs work refuses the
first source-file write with `[scope gate: …]`; a unit test keeps every bench prompt's class
and deliverables clear of that, so a cell loss with that line in its log is a bug, not a
measurement. `session_face` (2026-11-04, bead boubou-g11) is in the list: off, a turn's tool
categories come from its own instruction alone instead of every instruction of the session,
so a follow-up can change the tools sent (`[prefix] since the previous turn: tools changed`). `plan_hold` (2026-11-05, bead boubou-ear) is in the list: off,
a text reply ends the turn even while the plan the turn made has open items (Gate 5 runs at
`finish` only, as before).

No mean claim from one run per cell: on 2026-10-31 five coding cells re-run under one
configuration moved from 0.70 to 0.47. `--runs 3` scores every cell three times (`_r0`…`_r2`),
the summary shows `mean [min–max] n=3` per task and each arm's run means with their standard
deviation, which is the spread a difference between two results dirs has to clear:

```sh
python3 bench/lrab_h2h.py --arms rufous --task-root bench/lrab_ext --tiers tier6_editor \
    --policy coding,unattended --model gemma4:e2b --runs 3 \
    --results bench/results/surface_editor/gemma_e2b_x3
```

`--workdir-name proj` lays the cell out under `<cell>/proj` instead of `<cell>/workdir`, so the
absolute path in the model's system prompt ends in another word; the axis is recorded and the
rows read `dir=proj` when it varies. It is how the gemma4:e2b path quirk (profile rule
`rebase_workdir_prefix`) is separated into "copies the directory's name" or "says `workdir`
regardless".

## tier5_context (bead boubou-65d.9)

Inputs that do not fit a small context, so the agent has to search, run and summarise rather
than read everything. Run at `AGENT_CTX` 8192 / 16384 / 32768 / 65536; the summary groups cells
as `task@16k` etc. and the `compact` column counts compaction ladder steps. Baseline with
qwen3.5:9b (2026-10-29, `docs/changelog.md` "Context-pressure tier"): flat 1.0 at 16k and above

## tier6_editor and tier7_chat (docs/refactor.md step 10)

Briefs shaped like what a user types at a product surface, with no batch preamble, so a turn
policy can be measured on the work it will meet. Generated by `gen_surface.py`; the fixtures
are listed file by file so they land at the workdir root, the way a project sits under an
editor. Run them under the product presets with the driver's policy axis:

```sh
python bench/lrab_ext/gen_surface.py
python bench/lrab_h2h.py --arms rufous --task-root bench/lrab_ext --tiers tier6_editor \
    --policy coding,unattended --model qwen3.5:9b --results bench/results/surface_editor
python bench/lrab_h2h.py --arms rufous --task-root bench/lrab_ext --tiers tier7_chat \
    --policy general,unattended --model qwen3.5:9b --results bench/results/surface_chat
```

`--policy` runs `rufous run --policy <name>`: `unattended` is the batch harness, `general` and
`coding` the product presets, under which a text reply ends the run. For those cells the driver
writes the final reply (the last assistant text, else the `finish` summary) to `reply.md` in the
workdir before scoring, so an answer is checked the way a file is. The summary labels rows
`ED-02@coding`, `ED-02@unattended` when the axis varies, and the process table's
`named_files_missing` line is the named-deliverable gate's measure (ED-02's `fix_note.md`).
An untouched fixture scores 0 on every task (`test_surface.py` proves it against the scorer), so
a cell that crashed or read the files and quit is not paid the collateral credit.

## Harness-caused damage counters (bead boubou-bk9.14)

Three process-table columns read the loop's protocol lines for the class of loss the score
cannot see: the model did the right thing and the harness made it fail or wasted its call.
`shell` counts `[i] 🐚 [exit N]: <first stderr line>` lines (printed after a failed
`run_bash`) whose text is the shell's or an interpreter's complaint about the command itself
(`unescaped newline`, `unterminated string`, `command not found`, `syntax error`, `unexpected
EOF`); `bak` counts calls whose arguments mention `.bak`; `notes` counts the streak notes,
idle nudges and budget nudges put into the model's context. Read them before and after any
change to `exec.rs` or a ladder. On 2026-10-31 a live editor session had four shell errors in
a row from the old command unescape and eight `.bak` calls from the backup note's wording;
both would have shown here had the columns existed.

The same lines are kept for live sessions since 2026-10-31 (bead boubou-bmq): every surface
that names its session appends them to `~/.ollama_agent/sessions/<name>.log` behind a
timestamp (the editor otherwise keeps none of them; the ACP bridge has no channel for log
lines and tracing is at WARN), with a `[turn] <prompt head>` marker per editor prompt and
tracing warnings mirrored in as `[warn] …`. `python3 bench/session_metrics.py <log>` prints
the turns and the counters above for one session, so a Zed session is read the way a bench
cell is. `process_metrics` strips the stamps, so the regexes are unchanged.

Since 2026-10-31 (bead boubou-bj4) a `⚙` call line whose call did not do its job ends with a
status tag after the result head: ` ⟂error`, ` ⟂nochange`, or ` ⟂refused:<kind>[:user]` with the
gate's kind (`danger`, `risk`, `boundary`, `sensitive`, `system_dir`, `scope`, `substitute`,
`child`, `hook`) and `:user` when a person answered the dialog. `process_metrics.py` counts
`failed_calls` and `refused_calls` from the tag and falls back to the result's opening on an
untagged (older) log; `acp_convo.py` decides "landed" the same way. The text between `->` and
the tag is what the model read and may change without the readers noticing.

## Conversation rig (bead boubou-6gq)

Multi-turn sessions through the ACP server, scripted and checked per turn, for the features a
single prompt cannot show (scope gate, standing instructions, follow-ups, compaction, the
permission dialog): `bench/acp_convo.py` and the scripts under `bench/convo/` (its README has
the expectation keys and the table's columns).

## Replay corpus (bead boubou-bk9.13)

The tool calls real models made are regression data: `bench/replay_extract.py` turns a
rufous session transcript into `crates/rufous-kernel/tests/replay/<corpus>.jsonl` (the
session's working directory becomes `{workdir}`), and `cargo test -p rufous-kernel --test
replay` runs every entry through `Executor::prepare` (`as_written`: the shell gets exactly
that command, unblocked) or `run_tool` with a fixture. Add the calls of any session that
showed a harness fault, with the fixture that reproduces it, before fixing it.
