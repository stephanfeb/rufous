# Boubou-side LRAB extension

Tasks that live in this checkout, scored by Mingbird's LRAB scorer (`score_task.py`, imported
read-only by `bench/lrab_h2h.py`). Mingbird's tree is never written to. The layout is LRAB's
(`tasks/<tier>/*.json`, `fixtures/`), so the driver takes it as a task root:

```sh
python bench/lrab_ext/gen_pressure.py                      # regenerate (deterministic; tests check for drift)
python bench/lrab_h2h.py --arms boubou --task-root bench/lrab_ext \
    --ctx 16384,32768,65536 --model qwen3.5:9b --results bench/results/lrab_ctx
python bench/lrab_h2h.py --summary --results bench/results/lrab_ctx
```

Only the boubou arm runs here: Mingbird's own runner resolves fixtures against its own LRAB
root. Task checks are limited to the scorer's root-independent kinds (`exists`, `contains_any`,
`contains_groups`, `script_pass`); collateral damage is caught by a `check_collateral.py`
shipped with the fixture (prints `COLLATERAL OK` when every untouched definition is intact).

## hidden/ (bead boubou-65d.10)

Hidden scorer tests for WF-04 and LH-03, generated by `gen_hidden.py` (reads Mingbird's spec files
for their hashes). `lrab_h2h.py` copies `hidden/<task_id>/` into the workdir after the agent has
finished and scores the overlay's checks; `score.json["total_hidden"]`, summary `h=`. See
`docs/changelog.md` "Hidden scorer tests".

## tier5_context (bead boubou-65d.9)

Inputs that do not fit a small context, so the agent has to search, run and summarise rather
than read everything. Run at `AGENT_CTX` 8192 / 16384 / 32768 / 65536; the summary groups cells
as `task@16k` etc. and the `compact` column counts compaction ladder steps. Baseline with
qwen3.5:9b (2026-10-29, `docs/changelog.md` "Context-pressure tier"): flat 1.0 at 16k and above
with peaks of 6–13k tokens, so the ladder is only exercised at 8k (one timeout, one data loss).
Recency pruning A/B (bead boubou-65d.6): `AGENT_PRUNE_KEEP=5 python bench/lrab_h2h.py …` against
the default (off); the env passes through to every cell, use a separate `--results` dir per arm.

## tier6_editor and tier7_chat (docs/refactor.md step 10)

Briefs shaped like what a user types at a product surface, with no batch preamble, so a turn
policy can be measured on the work it will meet. Generated by `gen_surface.py`; the fixtures
are listed file by file so they land at the workdir root, the way a project sits under an
editor. Run them under the product presets with the driver's policy axis:

```sh
python bench/lrab_ext/gen_surface.py
python bench/lrab_h2h.py --arms boubou --task-root bench/lrab_ext --tiers tier6_editor \
    --policy coding,unattended --model qwen3.5:9b --results bench/results/surface_editor
python bench/lrab_h2h.py --arms boubou --task-root bench/lrab_ext --tiers tier7_chat \
    --policy general,unattended --model qwen3.5:9b --results bench/results/surface_chat
```

`--policy` runs `boubou run --policy <name>`: `unattended` is the batch harness, `general` and
`coding` the product presets, under which a text reply ends the run. For those cells the driver
writes the final reply (the last assistant text, else the `finish` summary) to `reply.md` in the
workdir before scoring, so an answer is checked the way a file is. The summary labels rows
`ED-02@coding`, `ED-02@unattended` when the axis varies, and the process table's
`named_files_missing` line is the named-deliverable gate's measure (ED-02's `fix_note.md`).
